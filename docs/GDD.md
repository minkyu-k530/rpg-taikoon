### v4-1. 무엇이 잘못됐나

플레이 테스트 피드백 세 가지.

1. **"가만히 있는데 뭘 해야 할지 모르겠다."** 플레이어가 하는 일은 뒤집기 탭과 배달뿐이었다. v0.3 원칙 4 "보는 재미가 하는 재미보다 우선"이 너무 강했다

3. **"타코야끼도 하고 싶다."**

그리고 그래픽이 **현실적이지 않다.** 기본 도형과 토온 셰이더로는 판교의 밤이 안 나온다.

### v4-3. 새 핵심 루프 — 자동으로 돌고, 손대면 배가 된다

모든 작업대(스테이션)에 **자동 모드**와 **직접 모드**가 있다.

| 스테이션 | 자동 (방치) | 직접 (클릭·1인칭) | 직접의 보상 |
|---|---|---|---|
| 붕어빵 틀 | 알아서 굽는다. 품질 점수 40~55 (알바가 있으면 오른다) | 꾹 눌러 반죽 → 팥 → 덮기 → 꺼내기 (v4-10) | 품질 점수 최대 80(+창의성 20) → 가격 최대 130%, 연속 고득점 콤보 |
| 타코야끼 판 (새) | 느리게 자동 (알바가 있으면 빨라진다) | 반죽 붓기 → 문어 → 굴리기 2회 타이밍 → 소스 | 동그랗게 익으면 '좋음', 콤보 |
| 어묵탕 | 항상 자동 | 국물 보충 탭 | 잠시 판매 속도 ↑ |
| 떡볶이 솥 | 자동으로 끓는다 | 젓기 탭 | 조리 시간 단축 |
| 손님 줄 | 순서대로 자동 응대 | 손님 클릭 = 즉시 주문 받기 | 대기 단축 + 팁 |
| 진열대 | — | 클릭 = 호객 | 10초간 유입 ↑ (쿨다운) |
| 단골 | 자동으로 호감 ↑ | 클릭 = 짧은 대화 | 호감 추가 ↑, 대사 해금 |

**방치 보상:** 게임을 꺼 둔 동안에도 장부가 쌓인다. 현실 4시간을 게임 하루로 보고, 자동 모드 수익의 50%를 최대 8시간까지 쌓는다. 8시간이면 방치 하루치와 같다.

**목표 수치** (구현 후 20회 이상 시뮬레이션 평균으로 맞춘다):
- 하루 순이익을 직접 플레이 / 방치만으로 나눈 값이 **1.6~2.0배**
- 방치만으로도 하루 순이익이 **0보다 크다** (실패 없음)
- 알바를 고용하면 방치 효율이 오른다. 하지만 직접 플레이를 넘지는 않는다

### v4-6. 배경 — SK AX 판교캠퍼스

**위치:** 경기 성남시 분당구 판교로255번길 38 (SK판교캠퍼스). 게임에서는 운중천 산책로 건너편에 캠퍼스가 보이도록 **실제 위치 관계를 각색**한다.

**고증 자료:** 네이버 로드뷰 2026년 6월 캡처 3장. 저작권 때문에 커밋하지 않고 로컬 `docs/ref/sk-campus/`에만 둔다.

**본관 (정면 사진 기준):**
- 지상 약 12층의 직육면체 슬래브
- 정면 왼쪽 약 1/4은 창 없는 은회색 금속 패널 벽이다. 위쪽에 빨간 SK 로고가 있다
- 오른쪽 3/4은 세로로 긴 파란 유리창 격자다. 창 사이에 밝은 회색 세로 필라스터가 있다. 아래 8층 정도에 해당한다
- 위쪽 약 4개 층은 수평으로 이어진 파란 커튼월 띠다
- 옥상 테두리는 어두운 루버 띠다
- 1층은 안으로 들어간 유리 출입구다. 위에 짙은 회색 캐노피 띠가 있고 SK 로고가 붙어 있다
- 앞마당은 넓은 화강석 포장이다. 소나무 여러 그루, 낮은 회양목 화단, 오른쪽에 주차 차단기 부스가 있다

**별관 (왼쪽 낮은 동):**
- 약 8층, 가로로 넓다
- 회청색 유리 격자 커튼월. 오른쪽 위에 SK 로고, 옥상에 난간이 있다

**뒷면:**
- 불규칙한 창 배열의 파란 유리 커튼월. 아래층은 흰 수평 루버다
- 붉은 벽돌 보도에 가로수(벚나무)가 서 있다. 근처에 "판교에듀파크" 표지가 있다

**표현 원칙:**
- 실측 비율에 가까운 매스와 재질(유리 반사, 금속 패널)로 만든다
- 밤에는 창 조명이 층별로 다르게 켜진다
- 로고는 비영리 개인 학습 목적이라는 전제 아래 간판으로 표시한다. **출시·수익화 전에는 상표 사용을 반드시 다시 검토하고 교체한다** (README 목표 2와 충돌하므로)

**주인공의 전 직장은 가상의 회사다.** 캠퍼스 옆 다른 오피스 건물이고, 실존 회사 이름은 쓰지 않는다.

### v4-10. 붕어빵 직접 조리와 품질 점수 (2026-11-27 요구사항)

뒤집기 탭 하나였던 붕어빵을 **누르는 길이로 양을 정하는 조리**로 바꾼다. 붕어빵 틀 1칸의 직접 조리 순서는 다음과 같다.

| 순서 | 조작 | 결과 |
|---|---|---|
| ① 반죽 | **꾹 누르는 동안** 반죽물이 부어진다. 떼면 멈춘다 | 아래 반죽 양 |
| ② 팥 | **꾹 누르는 만큼** 팥을 퍼 올린다 | 팥 양 |
| ③ 덮기 | **다시 꾹 눌러** 위 반죽을 붓는다. 떼면 뚜껑이 닫힌다 | 위 반죽 양, 굽기 시작 |
| ④ 꺼내기 | 적정 시간에 탭 | 익힘 정도 |

**품질 점수 (100점)**

| 항목 | 배점 | 만점 조건 (수치는 Balance에서 조정) |
|---|---|---|
| 반죽 양 | 20 | 아래 + 위 반죽 합이 틀 용량의 90~100%. 모자라거나 넘칠수록 줄어든다 |
| 팥 양 | 20 | 최대치의 70~90%. 너무 적거나(심심) 너무 많으면(터짐) 줄어든다 |
| 익힌 시간 | 40 | 적정 창(예: 18~22초) 안에 꺼냄. 덜 익거나 탈수록 줄어든다 |
| 창의성 | 20 | **나중에** 추가 재료(민트초코, 슈크림, 치즈 등)로 얻는다. 재료 시스템 전까지는 0점 |

**가격:** 기본가 × (0.7 + 0.6 × 기본점수/80) × (1 + 창의성/100). 기본점수는 반죽 + 팥 + 익힘(0~80)이다.
- 0점이어도 기본가의 70%로 팔린다 (실패 없음, v0.3의 "바삭한 붕어빵 700원"과 같은 자리)
- 기본점수 만점이면 130%다

**자동(방치):** 틀이 알아서 굽는다. 점수는 정해진 분포에서 뽑는다.
- 알바 없음: 기본점수 40~55
- 알바 Lv1: 50~62
- 알바 Lv2: 58~68
- 숙련된 직접 조리(70~80)를 넘지 않는다

**확장:** 점수 구조는 붕어빵이 기준이다. 타코야끼도 나중에 같은 틀(양·익힘·창의성)로 맞출 수 있게 Core의 품질 점수를 메뉴 공통 타입으로 둔다.

### v4-11. 최종 목표와 장소 — 판교에 내 집 마련 (2026-11-27 요구사항)

**최종 목표는 "판교에 내 집 마련"이다.** v4-2·v4-7의 "SK AX에 들어가는 것"을 이것으로 바꾼다. SK AX 판교캠퍼스는 목표가 아니라 **첫 장사 터의 배경**이 된다.

**장소는 차례로 열리며 가게가 커진다.**

| 공간 | 장소 | 성격 | 열리는 조건 (Balance에서 조정) |
|---|---|---|---|
| **1** | **SKALA 교육장 앞** (SK AX 판교캠퍼스 일대, v4-6 고증) | 교육생·직장인. 저녁 쉬는 시간과 수업 끝에 손님이 몰린다. 시작 장소 | 처음부터 |
| **2** | **판교역** | 유동 인구가 가장 많다. 출퇴근 피크가 있다. 노점에서 점포로 커진다 | 누적 순이익 기준 + 단골 수 기준 |
| 3+ | (나중에 정함) | — | — |

- 새 장소가 열려도 이전 장소는 남는다. 이전 장소는 알바에게 맡겨 방치 수익원이 된다. 방치와 직접 플레이 루프가 장소 단위로 커지는 구조다
- 공간마다 고증 자료(사진)가 필요하다. 1번은 v4-6, 2번 판교역은 사진을 받아서 시작한다

**내 집 마련:**
- "집 통장"에 목표 금액을 모으면 결말이 열린다
- 목표 금액과 장소별 수익 배율은 직접 플레이 기준 80일 안팎, 방치만이면 그보다 오래 걸리도록 맞춘다
- 방치만 해도 언젠가는 도달한다 (실패 없음)
- 실제 판교 집값을 그대로 쓰지 않는다. 게임 통화 기준으로 정한 목표다

**서사:** 장태수는 가상의 회사 "운중시스템"에서 권고사직을 당한다. SKALA 교육장 앞에서 붕어빵을 굽기 시작하고, 판교역으로 커져서, 판교에 집을 마련한다. STORY.md v2 개정을 이 선으로 고친다.

**실존 장소 표현:** SKALA·SK AX는 사용자가 실제 교육생이라는 전제의 비영리 학습 목적 표현이다. 출시 전 상표 재검토 원칙(v4-6)을 그대로 적용한다.

### 1-1. 왜 Unity가 아니라 웹인가

| | Unity (WebGL/모바일) | 웹 (R3F) |
|---|---|---|
| AI 개발 효율 | 씬·프리팹이 YAML/바이너리 → AI가 에디터 작업 불가, 사람이 수동 세팅 | **전부 텍스트 코드 → AI가 끝까지 작성·실행·확인 가능** |
| 첫 플레이까지 | 3~4주 | **당일** |
| 배포 | 20~40MB 로딩, iOS Safari 메모리 이슈 / 스토어 심사 | URL 하나 |
| 광고 수익 | 모바일 리워드 광고 CPM 높음 | 웹 광고 CPM 낮음 |
| 3D 품질 상한 | 높음 | 중간 (목표 비주얼은 재현 가능) |

수익 축만 Unity가 유리하다. 하지만 **재미가 검증되지 않은 상태에서 수익 축을 먼저 고르면 3개월을 날린다.** 웹으로 재미를 검증하고, 지표가 나오면 모바일로 이식한다.

## 2. 왜 이 소재인가 (적합성 판단)

| 기준 | 판단 |
|---|---|
| 스코프 | 전투·레벨디자인·밸런싱 난이도 전부 없음. 1인 3개월에 현실적인 유일한 장르 |
| 에셋 조달 | 현대 도시 + 일반인 군중은 무료 에셋이 가장 풍부한 영역 |
| 기술 리스크 | 군중 보행 + 타이머 경제. 새로 배울 기술 거의 없음 |

| 차별점 | 방치형 타이쿤은 레드오션. **단골 이야기 해금**이 유일한 차별 축 |

## 3. 레퍼런스 분석

### 3-1. 비주얼 (첨부 이미지: 조선 빌더)
그 스크린샷이 좋아 보이는 이유는 모델 퀄리티가 아니다. 셋으로 분해된다.

1. **군집 보행** — 10명 이상이 각기 다른 속도·방향으로 움직이고, 멈춰서 구경하고, 서로 비껴간다
2. **따뜻한 역광** — 낮은 각도 태양, 긴 그림자, 주황빛 림라이트
3. **얕은 피사계심도 + 살짝 내려본 고정 카메라** — 미니어처처럼 보이게 하는 핵심

→ 셋 다 에셋 품질과 무관하다. **로우폴리 무료 에셋으로도 저 느낌은 나온다.**

### 3-2. 무료 에셋의 스타일 불일치 대응 (리스크 상쇄책)
무료 에셋을 섞으면 재질·톤이 제각각이라 폴리싱 단계에서 비용이 터진다. 그래서 **에셋 재질을 그대로 쓰지 않는다.**

- 모든 캐릭터·소품 머티리얼을 **프로젝트 공용 토온 셰이더 1개로 교체**
- 색은 에셋 텍스처가 아니라 **팔레트 상수 12색**에서만 뽑는다
- 씬 전체에 톤매핑(ACES) + 야간 색보정 고정 → 출처가 달라도 같은 조명 아래 놓인다

### 3-3. 제작 방식 (유튜브 3편: AI 1인 개발 수익 공개)
공통 교훈:
- 완성도보다 **출시 횟수**가 수익을 만든다
- 광고비 태우기 전에 **오가닉 D1 리텐션**으로 검증한다
- AI는 코드를 쓰지만 **무엇을 만들지 정하는 건 사람** → 이 문서의 역할

→ 일정에 **숏폼 3편 제작**을 기능 개발과 동급으로 넣는다.

## 4. 핵심 설계 원칙 (모든 결정의 판단 기준)

1. **실패가 없다.** 태운 붕어빵은 손실이 아니라 "바삭한 붕어빵"으로 싸게 팔린다
2. **시간 압박이 없다.** 손님은 줄을 서서 기다리고, 재고가 없어도 화내지 않는다
3. **조작은 선택이지 의무가 아니다.** 직접 구우면 빠르고, 안 해도 어묵탕은 계속 팔린다
4. **보는 재미가 하는 재미보다 우선이다.** 10분 멍하니 볼 수 없으면 그래픽 작업을 시작하지 않는다
5. **숫자가 아니라 사람이 보상이다.** 업그레이드의 목적은 새 손님을 부르는 것

## 5. 배경 설정

**장소: 판교테크노밸리 운중천 산책로 끝, 다리 밑 공터**
(모델 지역: 성남시 분당구 삼평동 — 판교로255번길 일대)

- 시간대: 평일 저녁 7시 ~ 새벽 1시 고정
- 화면에 보이는 것: 하천 산책로, 다리, 가로등, 건너편 오피스 빌딩의 켜진 창들, 가로수, 자전거 거치대
- 소리: 물소리, 멀리 자동차, 라디오, 기름 끓는 소리

**왜 이 장소인가:** 오피스 빌딩의 켜진 창 = "아직 야근 중인 사람들"을 배경만으로 설명한다. 포장마차의 따뜻한 주황빛과 차가운 사무실 형광등이 한 화면에서 대비되는 것이 이 게임의 핵심 그림이다.

## 6. 게임 루프

### 6-1. 분 단위 루프 (영업 중)

```
반죽 → 굽기(탭) → 뒤집기(탭) → 진열 → 손님 구매 → 돈
          ↑                               │
          └──── 직원 고용 시 자동화 ───────┘

어묵탕 → (상시 준비됨, 조작 불필요) → 손님 구매 → 돈
```

- 붕어빵 틀 1칸: 굽기 20초. 중간에 **뒤집기 창(7~12초)** 이 열린다
  - 탭하면 정상 품질 → 1,000원
  - 놓치면 바삭한 붕어빵 → 700원 (**손실 아님, 변주**)
- 어묵탕: 조작 없이 상시 판매. 마진은 낮다. → **손 놓고 봐도 가게가 돌아간다는 보장**
- 진열대에 재고가 있으면 손님이 알아서 사 간다. 플레이어 개입 불필요
- 재고가 비면 손님은 잠시 기다리다 "다음에 올게요" 하고 간다 (호감도 변화 없음)

### 6-2. 세션 루프 (하루)

```
저녁 영업(6~8분) → 마감 정산 → 업그레이드/꾸미기 → 단골 이야기 열람 → 다음 날
```

### 6-3. 장기 루프 (리텐션)

```
매출↑ → 설비·메뉴 해금 → 손님 유입 유형 확장 → 새 단골 등장 → 이야기 해금 → 도감 완성
```

## 7. 손님 시스템 (게임의 심장)

### 7-1. 주민 생성
체형 3종 × 복장 6종 × 팔레트 색 × 걸음속도(±15%) → 20명 안팎이 전부 달라 보이게.

상태: `지나감` / `구경` / `구매` / `단골 방문`

### 7-2. 호감도 → 단골

| 단계 | 조건 | 해금 |
|---|---|---|
| 모르는 사람 | 초기 | 이름 없음 |
| 눈에 익음 | 3회 구매 | 이름 표시 |
| 단골 | 7회 | 대사 1줄, 도감 카드 생성 |
| 아는 사이 | 15회 | 대사 3줄, 개인 사연 1단락 |
| 가족 같은 | 30회 | 짧은 에피소드 + 영구 효과(그 손님이 다른 손님을 데려옴) |

### 7-3. 단골 8명 (1차 출시분, 판교 군상)

| # | 인물 | 한 줄 |
|---|---|---|
| 1 | 릴리즈 앞둔 백엔드 개발자 | 사흘째 같은 후드티. 어묵 국물만 두 번 받아간다 |
| 2 | 퇴근길 자전거 출퇴근족 | 헬멧 안 벗고 서서 먹는다 |
| 3 | 운중천 야간 러너 | 매일 같은 시간에 지나가다 어느 날 처음 멈춘다 |
| 4 | 강아지 산책시키는 입주민 | 강아지가 먼저 포장마차 앞에 선다 |
| 5 | 첫 직장 3개월 차 신입 | 사수 욕을 혼잣말로 한다 |
| 6 | 야근 끝난 디자이너 2인조 | 둘이 와서 다른 걸 시킨다 |
| 7 | 학원 끝난 고등학생 | 늘 현금이 모자란다 |
| 8 | 건너편 건물 경비 아저씨 | 교대 시간마다 들른다 |

**전부 대사 5줄 이내. 설교 없음, 결말 없음.** 그냥 판교 저녁에 있을 법한 사람들.

## 8. 경제 설계

**통화 1종(원)만 사용. 프리미엄 화폐 없음.**

| 항목 | 값 |
|---|---|
| 붕어빵 | 판매 1,000원 / 원가 300원 / 품질 하락 시 700원 |
| 어묵 | 판매 1,000원 / 원가 400원 / 조작 불필요 |
| 떡볶이 (2차 메뉴) | 판매 4,000원 / 원가 1,200원 / 조리 40초 |
| 손님당 구매량 | 1~3개 (평균 2) |
| 영업 1회 손님 수 | 초기 15~20명 → 후반 60명+ |
| 초기 1일 순이익 | 약 25,000원 |
| 1단계 업그레이드가 | 15,000 ~ 40,000원 (하루 1~2개 구매 가능) |

성장 곡선: 티어마다 순이익 ×2.5, 업그레이드 가격 ×3.

### 업그레이드 축 4개
1. **생산** — 붕어빵 틀 2칸 → 4 → 8 → 12
2. **메뉴** — 붕어빵 → 어묵 → 떡볶이 → 순대 → 계란빵(봄)
3. **설비** — 간판(유입↑), 온풍기(체류↑), 파라솔·의자(먹고 감), 조명, 라디오, 화분
4. **직원** — 굽기 자동화, 뒤집기 자동화 (고용하면 플레이어는 "보는 모드"로 전환)

### 날씨
맑음 / 눈 / 비. **눈 = 수요 1.5배, 비 = 유입 0.7배·체류 1.4배.**
비주얼 보상과 기계적 보상을 항상 일치시킨다.

- 보상형 광고: 매출 2배(1회), 오프라인 수익 2배, 업그레이드 즉시 완료
- 광고 제거 결제 + "응원 팩"
- **강제 전면광고 없음.** 잔잔함을 깨면 이 게임의 유일한 차별점이 사라진다

## 12. 일정 (12주)

| 주차 | 산출물 | 합격 기준 |
|---|---|---|
| 1~2 | 회색 박스 프로토타입 | **캡슐 20명이 걸어와 사 가는 화면을 10분 보고 싶은가** |
| 3~4 | 무료 에셋 + Mixamo 파이프라인 확정 → 주민 양산 | 20명이 각기 달라 보이는가 |
| 5~8 | 경제·업그레이드·단골·저장 | 30분 플레이에 끊김이 없는가 |
| 9~10 | 조명·사운드·파티클·UI 폴리싱 | 스크린샷 1장이 스크롤을 멈춰 세우는가 |
| 11~12 | 배포, 지표 수집, **숏폼 3편 제작** | D1 리텐션 35% 이상인가 |

**1단계에서 떨어지면 그래픽을 입히지 않고 주민 행동을 다시 만든다.**

## 13. 리스크

| 리스크 | 대응 |
|---|---|
| 군중이 어색하면 게임의 전제가 무너짐 | 1~2주차에 단독 검증. 분리력(separation) + idle 랜덤화 + 속도 변주 |
| 무료 에셋 스타일 불일치 | 공용 셰이더·팔레트·톤매핑으로 강제 통일 (3-2) |

| 3개월 내 미출시 | 메뉴/설비/단골 **수량**을 줄여 대응. 시스템은 줄이지 않음 |
| 심심함과 잔잔함의 경계 | 매 영업마다 최소 1개의 "변화"(새 손님·날씨·대사) 보장 |
| 웹 광고 수익 부족 | 재미 검증 후 모바일 이식으로 수익 축 전환 |
