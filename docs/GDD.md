## 1. 결정 기록 (v0.1 → v0.2)

| 항목 | 결정 | 근거 |
|---|---|---|
| 플랫폼 | 웹 우선 | 아래 1-1 표 참조 |
| 가게 | 분식 포장마차 (붕어빵 중심) | 붕어빵 단일은 겨울에 갇힘. 포장마차는 메뉴 확장으로 계절 제약 해소 |
| 배경 | 판교테크노밸리 운중천 산책로 | 본인 생활권 = 레퍼런스 사진을 직접 찍을 수 있음. IT 직장인 군상은 설명 없이 읽히는 소재 |
| 에셋 | 무료 에셋 + Mixamo | 비용 0. 스타일 통일은 **셰이더·조명·색보정으로 강제**해서 리스크 상쇄 (3-2 참조) |

### 1-1. 왜 Unity가 아니라 웹인가

| | Unity (WebGL/모바일) | 웹 (R3F) |
|---|---|---|
| AI 개발 효율 | 씬·프리팹이 YAML/바이너리 → AI가 에디터 작업 불가, 사람이 수동 세팅 | **전부 텍스트 코드 → AI가 끝까지 작성·실행·확인 가능** |
| 첫 플레이까지 | 3~4주 | **당일** |
| 배포 | 20~40MB 로딩, iOS Safari 메모리 이슈 / 스토어 심사 | URL 하나 |
| 광고 수익 | 모바일 리워드 광고 CPM 높음 | 웹 광고 CPM 낮음 |
| 3D 품질 상한 | 높음 | 중간 (목표 비주얼은 재현 가능) |

수익 축만 Unity가 유리하다. 하지만 **재미가 검증되지 않은 상태에서 수익 축을 먼저 고르면 3개월을 날린다.** 웹으로 재미를 검증하고, 지표가 나오면 모바일로 이식한다.

## 2. 왜 이 소재인가 (적합성 판단)

| 기준 | 판단 |
|---|---|
| 스코프 | 전투·레벨디자인·밸런싱 난이도 전부 없음. 1인 3개월에 현실적인 유일한 장르 |
| 에셋 조달 | 현대 도시 + 일반인 군중은 무료 에셋이 가장 풍부한 영역 |
| 기술 리스크 | 군중 보행 + 타이머 경제. 새로 배울 기술 거의 없음 |
| 마케팅 | "판교 붕어빵"은 숏폼 썸네일에서 1초 안에 읽힌다. 설명이 필요 없다 |
| 차별점 | 방치형 타이쿤은 레드오션. **단골 이야기 해금**이 유일한 차별 축 |

**결론: 소재는 적합. 단, 수치 성장만으로는 묻힌다. 감정 보상(단골)이 제1 기능이고 수치 성장은 그걸 여는 열쇠다.**

## 3. 레퍼런스 분석

### 3-1. 비주얼 (첨부 이미지: 조선 빌더)
그 스크린샷이 좋아 보이는 이유는 모델 퀄리티가 아니다. 셋으로 분해된다.

1. **군집 보행** — 10명 이상이 각기 다른 속도·방향으로 움직이고, 멈춰서 구경하고, 서로 비껴간다
2. **따뜻한 역광** — 낮은 각도 태양, 긴 그림자, 주황빛 림라이트
3. **얕은 피사계심도 + 살짝 내려본 고정 카메라** — 미니어처처럼 보이게 하는 핵심

→ 셋 다 에셋 품질과 무관하다. **로우폴리 무료 에셋으로도 저 느낌은 나온다.**

### 3-2. 무료 에셋의 스타일 불일치 대응 (리스크 상쇄책)
무료 에셋을 섞으면 재질·톤이 제각각이라 폴리싱 단계에서 비용이 터진다. 그래서 **에셋 재질을 그대로 쓰지 않는다.**

- 모든 캐릭터·소품 머티리얼을 **프로젝트 공용 토온 셰이더 1개로 교체**
- 색은 에셋 텍스처가 아니라 **팔레트 상수 12색**에서만 뽑는다
- 씬 전체에 톤매핑(ACES) + 야간 색보정 고정 → 출처가 달라도 같은 조명 아래 놓인다

### 3-3. 제작 방식 (유튜브 3편: AI 1인 개발 수익 공개)
공통 교훈:
- 완성도보다 **출시 횟수**가 수익을 만든다
- 광고비 태우기 전에 **오가닉 D1 리텐션**으로 검증한다
- AI는 코드를 쓰지만 **무엇을 만들지 정하는 건 사람** → 이 문서의 역할

→ 일정에 **숏폼 3편 제작**을 기능 개발과 동급으로 넣는다.

## 4. 핵심 설계 원칙 (모든 결정의 판단 기준)

1. **실패가 없다.** 태운 붕어빵은 손실이 아니라 "바삭한 붕어빵"으로 싸게 팔린다
2. **시간 압박이 없다.** 손님은 줄을 서서 기다리고, 재고가 없어도 화내지 않는다
3. **조작은 선택이지 의무가 아니다.** 직접 구우면 빠르고, 안 해도 어묵탕은 계속 팔린다
4. **보는 재미가 하는 재미보다 우선이다.** 10분 멍하니 볼 수 없으면 그래픽 작업을 시작하지 않는다
5. **숫자가 아니라 사람이 보상이다.** 업그레이드의 목적은 새 손님을 부르는 것

## 5. 배경 설정

**장소: 판교테크노밸리 운중천 산책로 끝, 다리 밑 공터**
(모델 지역: 성남시 분당구 삼평동 — 판교로255번길 일대)

- 시간대: 평일 저녁 7시 ~ 새벽 1시 고정
- 화면에 보이는 것: 하천 산책로, 다리, 가로등, 건너편 오피스 빌딩의 켜진 창들, 가로수, 자전거 거치대
- 소리: 물소리, 멀리 자동차, 라디오, 기름 끓는 소리

**왜 이 장소인가:** 오피스 빌딩의 켜진 창 = "아직 야근 중인 사람들"을 배경만으로 설명한다. 포장마차의 따뜻한 주황빛과 차가운 사무실 형광등이 한 화면에서 대비되는 것이 이 게임의 핵심 그림이다.

## 6. 게임 루프

### 6-1. 분 단위 루프 (영업 중)

```
반죽 → 굽기(탭) → 뒤집기(탭) → 진열 → 손님 구매 → 돈
          ↑                               │
          └──── 직원 고용 시 자동화 ───────┘

어묵탕 → (상시 준비됨, 조작 불필요) → 손님 구매 → 돈
```

- 붕어빵 틀 1칸: 굽기 20초. 중간에 **뒤집기 창(7~12초)** 이 열린다
  - 탭하면 정상 품질 → 1,000원
  - 놓치면 바삭한 붕어빵 → 700원 (**손실 아님, 변주**)
- 어묵탕: 조작 없이 상시 판매. 마진은 낮다. → **손 놓고 봐도 가게가 돌아간다는 보장**
- 진열대에 재고가 있으면 손님이 알아서 사 간다. 플레이어 개입 불필요
- 재고가 비면 손님은 잠시 기다리다 "다음에 올게요" 하고 간다 (호감도 변화 없음)

### 6-2. 세션 루프 (하루)

```
저녁 영업(6~8분) → 마감 정산 → 업그레이드/꾸미기 → 단골 이야기 열람 → 다음 날
```

### 6-3. 장기 루프 (리텐션)

```
매출↑ → 설비·메뉴 해금 → 손님 유입 유형 확장 → 새 단골 등장 → 이야기 해금 → 도감 완성
```

## 7. 손님 시스템 (게임의 심장)

### 7-1. 주민 생성
체형 3종 × 복장 6종 × 팔레트 색 × 걸음속도(±15%) → 20명 안팎이 전부 달라 보이게.

상태: `지나감` / `구경` / `구매` / `단골 방문`

### 7-2. 호감도 → 단골

| 단계 | 조건 | 해금 |
|---|---|---|
| 모르는 사람 | 초기 | 이름 없음 |
| 눈에 익음 | 3회 구매 | 이름 표시 |
| 단골 | 7회 | 대사 1줄, 도감 카드 생성 |
| 아는 사이 | 15회 | 대사 3줄, 개인 사연 1단락 |
| 가족 같은 | 30회 | 짧은 에피소드 + 영구 효과(그 손님이 다른 손님을 데려옴) |

### 7-3. 단골 8명 (1차 출시분, 판교 군상)

| # | 인물 | 한 줄 |
|---|---|---|
| 1 | 릴리즈 앞둔 백엔드 개발자 | 사흘째 같은 후드티. 어묵 국물만 두 번 받아간다 |
| 2 | 퇴근길 자전거 출퇴근족 | 헬멧 안 벗고 서서 먹는다 |
| 3 | 운중천 야간 러너 | 매일 같은 시간에 지나가다 어느 날 처음 멈춘다 |
| 4 | 강아지 산책시키는 입주민 | 강아지가 먼저 포장마차 앞에 선다 |
| 5 | 첫 직장 3개월 차 신입 | 사수 욕을 혼잣말로 한다 |
| 6 | 야근 끝난 디자이너 2인조 | 둘이 와서 다른 걸 시킨다 |
| 7 | 학원 끝난 고등학생 | 늘 현금이 모자란다 |
| 8 | 건너편 건물 경비 아저씨 | 교대 시간마다 들른다 |

**전부 대사 5줄 이내. 설교 없음, 결말 없음.** 그냥 판교 저녁에 있을 법한 사람들.

## 8. 경제 설계

**통화 1종(원)만 사용. 프리미엄 화폐 없음.**

| 항목 | 값 |
|---|---|
| 붕어빵 | 판매 1,000원 / 원가 300원 / 품질 하락 시 700원 |
| 어묵 | 판매 1,000원 / 원가 400원 / 조작 불필요 |
| 떡볶이 (2차 메뉴) | 판매 4,000원 / 원가 1,200원 / 조리 40초 |
| 손님당 구매량 | 1~3개 (평균 2) |
| 영업 1회 손님 수 | 초기 15~20명 → 후반 60명+ |
| 초기 1일 순이익 | 약 25,000원 |
| 1단계 업그레이드가 | 15,000 ~ 40,000원 (하루 1~2개 구매 가능) |

성장 곡선: 티어마다 순이익 ×2.5, 업그레이드 가격 ×3.

### 업그레이드 축 4개
1. **생산** — 붕어빵 틀 2칸 → 4 → 8 → 12
2. **메뉴** — 붕어빵 → 어묵 → 떡볶이 → 순대 → 계란빵(봄)
3. **설비** — 간판(유입↑), 온풍기(체류↑), 파라솔·의자(먹고 감), 조명, 라디오, 화분
4. **직원** — 굽기 자동화, 뒤집기 자동화 (고용하면 플레이어는 "보는 모드"로 전환)

### 날씨
맑음 / 눈 / 비. **눈 = 수요 1.5배, 비 = 유입 0.7배·체류 1.4배.**
비주얼 보상과 기계적 보상을 항상 일치시킨다.

## 10. 비주얼 / 조작

- 화면: **세로 우선**, 가로에서는 카메라가 넓어지는 반응형 (웹이므로 둘 다 지원)
- 카메라: 고정 쿼터뷰, 피사계심도 ON, 흔들림 없음
- 시간대: 밤 고정. 주황 포장마차 조명 + 푸른 그림자 대비
- 조작: 탭/클릭만. 드래그·핀치 없음
- 캐릭터: 로우폴리 + 공용 토온 셰이더. **직접 모델링하지 않는다**

---

## 11. 수익화 (출시 시점)

- 보상형 광고: 매출 2배(1회), 오프라인 수익 2배, 업그레이드 즉시 완료
- 광고 제거 결제 + "응원 팩"
- **강제 전면광고 없음.** 잔잔함을 깨면 이 게임의 유일한 차별점이 사라진다

## 12. 일정 (12주)

| 주차 | 산출물 | 합격 기준 |
|---|---|---|
| 1~2 | 회색 박스 프로토타입 | **캡슐 20명이 걸어와 사 가는 화면을 10분 보고 싶은가** |
| 3~4 | 무료 에셋 + Mixamo 파이프라인 확정 → 주민 양산 | 20명이 각기 달라 보이는가 |
| 5~8 | 경제·업그레이드·단골·저장 | 30분 플레이에 끊김이 없는가 |
| 9~10 | 조명·사운드·파티클·UI 폴리싱 | 스크린샷 1장이 스크롤을 멈춰 세우는가 |
| 11~12 | 배포, 지표 수집, **숏폼 3편 제작** | D1 리텐션 35% 이상인가 |

**1단계에서 떨어지면 그래픽을 입히지 않고 주민 행동을 다시 만든다.**

## 13. 리스크

| 리스크 | 대응 |
|---|---|
| 군중이 어색하면 게임의 전제가 무너짐 | 1~2주차에 단독 검증. 분리력(separation) + idle 랜덤화 + 속도 변주 |
| 무료 에셋 스타일 불일치 | 공용 셰이더·팔레트·톤매핑으로 강제 통일 (3-2) |
| 방치형 레드오션에 묻힘 | 단골 이야기를 마케팅 전면에. "숫자 올리는 게임"으로 홍보하지 않음 |
