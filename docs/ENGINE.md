# 스킨드 캐릭터 엔진 검증

## 질문과 방법

실제 게임 장면 위에서 스킨드 캐릭터 60명이 걸을 때 웹 렌더링이 목표 성능을 유지하는가. 개발 전용 `/bench.html`에서 기존 `Environment`와 `Stall`을 그대로 렌더링하고, 코드로 생성한 캐릭터를 카메라에 보이는 산책로 안에서 왕복 이동시켰다. 카메라는 게임의 `CameraRig`와 동일하게 가로 FOV 40/세로 FOV 54, 위치와 시선 대상을 적용했다. 각 캐릭터는 15개 뼈의 `SkinnedMesh`, 독립 `Skeleton`과 `AnimationMixer`를 가지며 지오메트리는 공유한다. 게임 시뮬레이션은 tick하지 않았다.

각 조건은 3초 워밍업 뒤 10초간 프레임 간격을 수집했다. 평균 fps는 프레임 수를 경과 시간으로 나눈 값, p95 프레임 시간은 간격의 95백분위, 최소 fps는 가장 긴 간격의 역수다. 프레임 작업 시간은 매 프레임 `mixer.update` 시작부터 `gl.render` 종료까지 `performance.now()`로 잰 CPU 쪽 시간이며 평균과 p95를 함께 기록했다. 보이는 캐릭터 수는 종료 시점에 각 캐릭터의 경계 구가 카메라 프러스텀과 만나는 수다. `calls`와 `triangles`는 종료 시점의 `renderer.info.render` 값이다. CPU 4x·6x는 Chrome DevTools Protocol `Emulation.setCPUThrottlingRate`를 적용했다. 기준선은 현재 게임 `/` 페이지를 별도 스크립트로 열어 같은 프레임 간격 방식으로 측정했다.

## 환경

- MacBook Pro (Mac17,2), Apple M5, 메모리 16GB
- Google Chrome 158.0.8127.38, 헤드리스 새 모드, 1280×800 CSS 픽셀, DPR 1
- Chrome 실행 플래그: `--enable-gpu --use-gl=angle --use-angle=metal --disable-gpu-vsync --disable-frame-rate-limit`
- WebGL 렌더러 원문: `ANGLE (Apple, ANGLE Metal Renderer: Apple M5, Unspecified Version)` — SwiftShader가 아닌 Apple Metal GPU
- 상한 해제 근거: 60명·3,000정점·1x에서 평균 285.8fps, 60명·12,000정점·4x에서 평균 149.0fps. 약 60fps 상한을 넘었다
- 개발 서버 `npm run dev`, 기본 `scene=1`, `shadows=1`; 표의 `M5 Metal`은 위 렌더러 원문을 뜻한다

## 판정

**이번 데스크톱 측정에서는 웹을 유지한다.** 4x CPU 스로틀에서 60명, 상한 해제 평균 30fps 이상, p95 프레임 시간 50ms 이하가 목표다. 시험한 최대 조건인 **목표·실제 12,000정점/명**에서 평균 **149.0fps**, p95 프레임 **13.3ms**, p95 작업 **10.9ms**였고, 60명 모두 프러스텀 안에 있었다. 반복 측정도 150.1fps/p95 프레임 11.6ms로 통과했다. 데스크톱(Apple M5)·CPU 4x 기준으로 확인된 정점 범위는 **최소 12,000정점/명**이며, 모바일 에셋 예산은 실제 폰 측정 후 확정한다. 이는 시험 범위의 상한을 통과했다는 뜻이며 더 높은 정점 수의 한계는 아직 측정하지 않았다.

## 이전 측정의 오류와 한계

이전 벤치는 게임 `CameraRig`가 없고 이동 좌표를 x=15에서 클램핑해 약 36%가 프러스텀 밖에 있었다. 또 대부분 60fps 화면 갱신 상한에 묶여 정점 수별 여유를 구분하기 어려웠다. 이번에는 카메라와 경로를 고쳐 모든 행에서 요청 인원이 보였고 상한을 해제했다.

상한 해제 fps는 브라우저의 프레임 제출 속도이며 GPU 작업 완료를 동기화한 처리량은 아니다. 프레임 작업 시간도 CPU 쪽 `gl.render` 호출까지이며 GPU 완료 시간이나 게임 씬의 다른 `useFrame` 작업은 포함하지 않는다. CPU 스로틀은 GPU를 늦추지 않아 **실제 폰 측정을 대신하지 않는다**. 조건은 각 한 번씩 측정했고 일부 6x 수치가 4x보다 높거나 6,000정점이 12,000정점보다 느려 외부 부하와 실행 변동이 드러난다. 실제로 60명·6,000정점·4x 반복은 67.3fps에서 138.9fps로 달랐다. 지오메트리·재질은 공유되며 실제 에셋의 텍스처·재질 수·투명도 비용은 포함하지 않았다. 게임 기준선 첫 방문에서 파비콘 요청 404 한 건이 있었지만 벤치 행렬의 브라우저 오류는 0건이었다.
