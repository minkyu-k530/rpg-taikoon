# rpg-freestyle

골목 어귀의 작은 노점에서 시작해, 지나가던 동네 사람들이 단골이 되어 가는 걸 지켜보는 잔잔한 가게 타이쿤.

## 목표

1. 만드는 사람 본인의 재미
2. 출시와 수익
3. 위 둘의 결과로 따라오는 취업 포트폴리오

## 정해진 것

- 배경: 현대, 골목 한 블록
- 엔진: Unity
- 첫 출시 범위는 3개월 분량으로 제한

## 아직 정해지지 않은 것

- 플랫폼 (모바일을 가정하고 계획했으나 확정 전. Steam이면 유료 판매가 되어 콘텐츠 분량을 2~3배로 잡아야 함)
- 가게 종류 (붕어빵/분식 노점을 예시로 둠)
- 캐릭터 에셋을 어디서 구할지

## 첫 출시 범위

| 항목 | 내용 |
|---|---|
| 맵 | 골목 한 블록, 고정 카메라 하나 |
| 주민 | 체형 3~4종에 옷과 색을 조합해 20명 안팎으로 보이게 |
| 애니메이션 | 걷기, 대기, 구경하기, 받기, 먹기 등 5~6개 |
| 조작 | 만들기와 진열만 터치, 나머지는 주민이 알아서 움직임 |
| 성장 | 메뉴 추가, 노점 꾸미기, 단골별 짧은 이야기 해금 |
| 수익 | 보상형 광고와 광고 제거 구매 (강제 광고 없음) |

넣지 않는 것: 전투, 자유 이동, 여러 지역, 멀티플레이.

## 핵심 루프

진열·준비 → 손님 방문 → 판매 → 번 돈으로 확장 → 새 손님 유형 해금

## 잔잔함의 기준

분위기는 모델 품질이 아니라 주민 행동에서 나온다.

- 주민마다 걷는 속도와 보폭이 조금씩 다르다
- 목적지 앞에서 서성이고, 구경하고, 고개를 돌린다
- 걷기, 대기, 집기, 대화 동작이 끊기지 않고 이어진다
- 실패나 시간 압박이 없다

## 일정

1. 1~2주: 회색 박스 프로토타입. 캡슐 주민 10명이 걸어와 물건을 사고 돌아간다
2. 3~4주: 캐릭터 1명으로 파이프라인을 확정한 뒤 주민 양산
3. 5~8주: 성장, 단골 이야기, 저장
4. 9~12주: 조명, 사운드, 광고 연동, 스토어 등록

프로토타입 합격 기준은 하나다. 그 화면을 10분 동안 멍하니 보고 싶은가. 아니라면 그래픽을 입히기 전에 주민 행동을 고친다.

## 다른 컴퓨터에서 이어서 작업하기

Git LFS가 필요하다 (모델, 텍스처, 오디오가 LFS로 관리됨).

```sh
brew install git-lfs
git lfs install
git clone https://github.com/JungMK0720/rpg-freestyle.git
```

Unity 프로젝트는 아직 생성되지 않았다. 이 레포 루트에 Unity 프로젝트를 만들면 `.gitignore`와 `.gitattributes`가 그대로 적용된다.

## 작업 규칙

- `main`에 직접 커밋하지 않는다. 브랜치를 만들어 작업하고 PR로 올린다.
- Unity를 배치 모드로 실행해 컴파일 오류가 없는 것을 확인한 PR만 merge한다. 확인하지 못했으면 PR만 올려 둔다.
- 가정한 내용과 확인하지 못한 것은 PR 본문에 적는다.
- 에셋 구매, 계정 생성, 스토어 등록은 사람이 직접 한다.

## 첫 실행 지시문 (1회용)

> 이 절은 한 번만 쓰고 지운다. 아래 작업을 PR로 올릴 때, 같은 PR에서 이 절 전체를 README에서 삭제하고 위의 "아직 정해지지 않은 것"과 "다른 컴퓨터에서 이어서 작업하기"를 실제 상태에 맞게 고친다. 이 절이 README에 남아 있다면 아직 실행되지 않은 것이다.

### 사람이 먼저 해 둘 것

1. Unity Hub를 설치해 로그인하고 Unity 6 LTS를 iOS/Android 빌드 모듈과 함께 설치한다.
2. `gh auth login`으로 이 레포에 push 권한이 있는 계정에 로그인한다.
3. Claude 세션의 권한 모드를 파일 수정과 명령 실행을 묻지 않는 모드로 바꾼다.
4. 전원을 연결하고 컴퓨터가 잠들지 않게 한다.

그다음 Claude에게 이렇게 말한다: "README의 첫 실행 지시문대로 진행해줘."

### Claude가 할 일

README 일정의 1단계인 회색 박스 프로토타입을 만든다.

- 이 레포 루트에 Unity 6 프로젝트를 만든다 (3D, URP, 모바일 세로 화면 기준).
- 골목 한 블록을 만든다. 바닥, 건물 박스 몇 개, 가운데 노점 하나, 고정 카메라.
- 캡슐 주민 10명이 NavMesh로 걸어 다닌다. 주민마다 속도가 조금씩 다르다. 일부는 노점 앞에 줄을 서서 물건을 사고 돌아가고, 나머지는 그냥 지나간다.
- 노점은 일정 시간마다 상품이 만들어지고, 팔리면 돈이 오른다. 화면 위에 돈을 표시한다.
- 씬은 에디터 스크립트로 자동 구성해서 메뉴 한 번으로 다시 만들 수 있게 한다.
- 미확정 항목은 플랫폼은 모바일, 가게는 붕어빵 노점으로 가정한다.

진행 방식:

- 위 "작업 규칙"을 따른다.
- 사람이 자리에 없으니 질문하지 말고 합리적인 기본값으로 진행한다.
- Unity가 설치되어 있지 않거나 라이선스가 활성화되지 않았으면 코드와 에디터 스크립트까지만 작성해 PR을 올리고, merge하지 않은 채 그 사실을 PR 본문 맨 위에 적는다.
- 끝나면 사람이 Unity에서 재생해 확인할 방법(어떤 씬을 열고 어떤 메뉴를 누르는지)을 PR 본문에 적는다.
