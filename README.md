판교 운중천 산책로 옆 분식 포장마차. 실패도 시간 압박도 없고, 지나가던 사람이 단골이 되어 가는 걸 지켜보는 잔잔한 가게 타이쿤.

## 지금 상태

캐릭터 에셋은 아직 없다. 전부 기본 도형이다. 그 외에는 **하루가 끝까지 돌아간다.**

### 돌아가는 것

- **군중** — 고정 명부 20명이 각자 다른 속도로 산책로를 걷는다. 서로 비껴가고, 멈춰서 구경하고, 줄을 서고, 사서 먹고 간다
- **단골** — 같은 사람이 다시 온다. 3회 이름, 7회 대사, 15회 사연, 30회 에피소드가 열린다. 도감에 쌓인다
- **조리** — 붕어빵(뒤집기 창), 어묵(조작 없음), 떡볶이(40초에 4그릇). 실패는 없다. 뒤집기를 놓치면 바삭한 붕어빵으로 싸게 팔린다
- **날씨** — 맑음·눈·비. 눈이 오면 더 사 먹고, 비가 오면 사람은 적지만 오래 머문다. 마감 때 내일 예보가 나온다
- **소리** — 오디오 파일 없이 Web Audio로 합성. 굽는 틀이 늘면 기름 소리가 커지고, 눈이 오면 전체가 먹먹해진다
- **성장** — 틀·간판·온풍기·어묵탕·떡볶이 솥·알바. 알바를 쓰면 손을 놓고 구경만 해도 된다
- **저장** — localStorage. 날짜·돈·설비·단골 기록이 남는다. 설정에서 지울 수 있다

### 측정한 수치 (게임 내 고속 시뮬레이션, 각 조건 20회 평균)

| 조건 | 하루 매출 |
|---|---|
| 1일차 기본, 성실히 뒤집음 | 약 18,000원 |
| 틀 2개 + 어묵 | 25,500원 |
| 틀 6개 + 떡볶이 + 알바 Lv2 | 33,200원 |
| 눈 오는 날 (설비 갖춘 뒤) | 맑음 대비 +16% |

단골 8명 전원과 면식까지 **12일**, '가족 같은' 단계는 22~25일차 예상.

### 아직 없는 것

캐릭터 에셋, 광고·결제, 오프라인 수익, 튜토리얼.

## 기술 선택

| | 선택 | 이유 |
|---|---|---|
| 플랫폼 | 웹 | 첫 플레이까지 당일. 재미 검증 후 모바일 이식 |
| 렌더링 | Three.js + @react-three/fiber | 전부 텍스트 코드라 AI가 끝까지 작성·검증 가능 |
| 상태 | 클래스 하나 (`src/game/sim.ts`) | 상태 라이브러리 없이 충분. React는 10Hz 스냅샷만 받는다 |
| 소리 | Web Audio 합성 | 파일 없이 상태에 반응하는 소리를 만든다 |

Unity를 쓰지 않은 이유는 [`docs/GDD.md` 1-1](docs/GDD.md)에 적어 두었다.

## 구조

```
src/
  game/
    config.ts       밸런싱 수치와 씬 좌표계. 숫자는 전부 여기
    sim.ts          시뮬레이션. React·Three.js·오디오 의존 없음
    residents.ts    주민 명부 20명. 단골 8명의 외형·대사·에피소드
    weather.ts      날씨별 유입·구매·체류 배율
    audio.ts        Web Audio 합성
    save.ts         localStorage
    useSim.ts       React 다리. UI는 10Hz 스냅샷만 본다
  scene/
    Environment.tsx 산책로·하천·난간·가로등·건너편 오피스
    Stall.tsx       포장마차, 붕어빵 틀, 어묵·떡볶이 솥, 사장님과 알바
    Crowd.tsx       주민 렌더링. 위치는 매 프레임 sim에서 직접 읽는다
    Weather.tsx     눈·비 입자
    textSprite.ts   이름표·말풍선 캔버스 텍스처
  ui/HUD.tsx        상단 정보, 뒤집기 버튼, 도감, 설정, 마감 정산
```

### 지켜야 하는 규칙 셋

1. **매 프레임 바뀌는 값은 React state에 넣지 않는다.** 위치·색은 `useFrame`에서 Three.js 객체를 직접 건드리고, React는 10Hz 스냅샷만 리렌더한다
2. **`sim`은 Three.js도 오디오도 import 하지 않는다.** 소리는 `sim.onEvent` 콜백 하나로만 나간다. 이걸 깨면 하루를 수십 번 고속으로 돌려 수치를 재는 검증 방식이 무너진다
3. **밸런싱 수치는 20회 이상 평균으로 본다.** 하루 매출의 분산이 커서 8회로는 20%짜리 가짜 효과가 보인다 (DEVLOG PR #7 참조)

## 개발용 핸들

개발 모드에서 브라우저 콘솔에 두 객체가 열린다.

```js
__sim.villagers.length        // 거리에 있는 사람 수
__sim.stats                   // 오늘 매출/판매/손님
__sim.dayTime = 149           // 마감 화면으로 점프
__sim.weather = 'snow'        // 날씨 바꾸기
__audio.rms()                 // 지금 나가는 소리의 세기

// 하루를 즉시 끝까지 돌리기 (렌더링 없이)
while (__sim.open) { __sim.molds.forEach((m, i) => __sim.flip(i)); __sim.tick(0.1); }
__sim.report
```

## 잔잔함의 기준

분위기는 모델 품질이 아니라 주민 행동에서 나온다.

- 주민마다 걷는 속도와 보폭이 조금씩 다르다
- 목적지 앞에서 서성이고, 구경하고, 고개를 돌린다
- 실패나 시간 압박이 없다

합격 기준은 하나다. **그 화면을 10분 동안 멍하니 보고 싶은가.** 아니라면 그래픽을 입히기 전에 주민 행동을 고친다.
